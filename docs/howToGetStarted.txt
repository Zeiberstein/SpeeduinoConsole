The Speeduino can react to commands on its serial ports. One of those ports is the
regular USB port, which TunerStudio also uses.

For this project it is more practical to leave the USB connection dedicated to
TunerStudio and use Speeduino's secondary serial port for the display helper Arduino.
That way there is no need to swap cables.

Enable the secondary interface in TunerStudio under Accessories. The firmware in this
repository expects the protocol to be set to "Generic (Fixed List)".
See docs/images/enableSecondarySerialInterface.png.

On a Speeduino based on the Arduino Mega 2560, the secondary interface is tied to
Serial3:
- Speeduino TX3 = pin 14
- Speeduino RX3 = pin 15

See docs/images/pinoutMega2560.png for their location. In
docs/images/connectingPin14and15.jpg you can see an example of how these wires were
added on the Speeduino board.

I used 10k resistors in series with the serial wires. The goal is simply to make the
connection a bit more forgiving if a wire is accidentally shorted. For this low-current
serial link, that extra resistance has not caused problems in practice.

Current helper-Arduino wiring

The current Lomax version no longer uses a software serial port on pins 10 and 11.
The helper firmware now uses the Arduino Mega 2560 hardware serial port Serial1.

Helper Arduino Serial1 pins:
- RX1 = pin 19
- TX1 = pin 18

Wire the two boards as a crossed serial connection:
- Speeduino TX3 pin 14 -> helper Arduino RX1 pin 19
- Speeduino RX3 pin 15 -> helper Arduino TX1 pin 18

The Speeduino and helper Arduino must also share a common ground. This is
required even when the boards are powered from different sources, such as USB on
one board and a battery pack on the other. Without a shared ground reference,
the UART signal levels can float relative to each other and cause intermittent
packet read errors.

Because of that change, the helper board must be Mega-2560-compatible or another
board that offers the same hardware serial port in the code. The current PlatformIO
configuration targets an Arduino Mega 2560.

The helper firmware lives in src/main.cpp in this repository.

Protocol changes in this version

This version sends the lowercase "n" command to Speeduino, not the older "a" command.
That returns the larger fixed secondary-serial data block, which gives the display code
access to more live values.

The serial read loop was also tightened up:
- it validates the response header before accepting a packet
- it uses the payload length from the packet itself
- it detects incomplete packets
- it discards unexpected trailing bytes
- it keeps a fixed polling interval so the display updates stay predictable

In practice this makes the display more tolerant of bad serial data and quicker to
recover when a read goes wrong.
